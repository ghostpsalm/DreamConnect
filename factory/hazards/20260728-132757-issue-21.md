# Hazards — DreamConnect installer, issue #21 (DREAMCONNECT_HOST_ACCOUNT reversibility)

Read by the `breaker` before every red team; appended by `/submit`. Not a bug list — the issue tracker
holds work. This holds *where trouble has been found before, and what has already been ruled out*.

A rule-out is evidence only while the code it names is unchanged, which is why every row carries a path
and the commit it was established at. Expiry is checked with **both** `git log <commit>..HEAD -- <path>`
and `git diff HEAD -- <path>` — a red team works on an uncommitted tree, so `git log` alone cannot see
the change it is there to attack.

## Ruled out — probed with evidence, no defect found
| hypothesis | path | evidence | established at |
|---|---|---|---|
| `local LC_ALL=C` in `valid_account_name` is load-bearing, not cosmetic, and doesn't leak into the caller's scope | install-lib.sh :: `valid_account_name` | Mutant with the `LC_ALL=C` line removed accepts accented letters (`é`) under `en_US.utf8`/`fr_FR.utf8`/`sv_SE.utf8`; real code rejects them under all four locales tested (incl. C); caller's own `$LC_ALL`/locale-dependent behaviour confirmed unchanged after the call returns | 7acf24a |
| All 7 reserved-name-guard call sites (`root`\|`user`\|`local`) are load-bearing, not decorative | install.sh entry-point case; install-lib.sh :: `host_account_installable` (both paths), `configure_no_idle_lock`, `remove_no_idle_lock`, `ensure_host_account`, `remove_accountsservice_marker`, `host_account_removable` | Mutation sweep: neutering any one site's reserved-case individually produces at least one failing test; no site's guard is unreachable or vacuous | 7acf24a |
| install.sh's Site A (uninstall(), skip-and-warn on an unusable `$target_home`) doesn't mask a real problem or leave `$target_home` used unsafely elsewhere in the function | install.sh :: `uninstall()` | Full call-order trace: nothing between Site A and `remove_no_idle_lock` uses `$target_home` unguarded; `remove_no_idle_lock` re-validates it independently | 7acf24a |
| `uninstall_host_account`'s absent-account short-circuit doesn't create a bypass when install.state records a reserved/malformed name that also has no passwd entry | install-lib.sh :: `uninstall_host_account`, `remove_no_idle_lock`, `remove_accountsservice_marker` | Live trace: both functions refuse `user`/`local`/malformed names independently regardless of passwd-entry absence; nothing destructive runs; only cost is a misleading (not incorrect-acting) "removed" message in install.sh's own output | 7acf24a |
| `valid_home_dir`'s normalization loops (collapsing `//`, dropping `.` components) terminate and aren't a DoS vector | install-lib.sh :: `valid_home_dir` | 38 adversarial forms tested incl. `/root//`, `/root/./`, `/./`, tab/newline/trailing-space mixes; a ~40KB pathological path (`/./` repeated) completes in ~0.5s — loops strictly shorten the string each iteration, non-issue for passwd-sourced data | 7acf24a |
| No 8th call site consumes an account name or home path without going through one of the 7 documented guards | install.sh, install-lib.sh (whole-file grep) | `enable_autologin` has exactly 2 callers (both covered); `uninstall_host_account:687`-equivalent path is gated by `host_account_removable`; `disable_autologin` takes no name argument | 7acf24a |

## Unprobed — no oracle available

|---|---|---|
