# Hazards — dreamconnect (issue #27, stale shm frame owned by a different uid)

## Held — found once, now guarded by a test

| hazard | path | test that holds it | commit |
|---|---|---|---|
| /dev/shm's sticky bit (mode 1777) means an unprivileged process can't unlink a file genuinely owned by a different uid — os.unlink() itself raises PermissionError (EPERM), distinct from the open's EACCES. A recovery path that only guards os.open() will crash on this instead of recovering. | runtime/dreamconnect_daemon.py (FrameBuffer.ensure) | runtime/test_daemon.py::TestFrameBufferEnsureStickyBitUnlink::test_ensure_raises_permission_error_for_a_foreign_owned_file_under_sticky_bit_dir | 8a9860c |
| A shell function that unlinks a shared-namespace file unconditionally (rather than gating on ownership) will delete a live, correctly-owned file on every routine invocation, not only the migration/foreign-owner case it was written for. | install-lib.sh (reclaim_stale_shm_frame) | test_install.sh::test_reclaim_stale_shm_frame_leaves_a_file_already_owned_by_the_target_uid_untouched | 8a9860c |
| The call-site ordering that makes a foreign-uid cleanup actually effective (cleanup must run before the consumer that would otherwise open the stale/removed file) is easy to silently break by reordering, and nothing but a direct code read catches it unless pinned. | install.sh (reclaim_stale_shm_frame call site vs. SC restart / daemon enable) | test_install.sh::test_install_sh_reclaims_the_stale_shm_frame_before_sc_restart_and_daemon_enable | 8a9860c |

## Ruled out — probed with evidence, no defect found

| hypothesis | path | evidence | established at |
|---|---|---|---|
| ControlServer.run()'s unix-socket bind needs the same unlink-and-retry treatment as the shm frame ("by parity", per issue #27's own text). | runtime/dreamconnect_daemon.py (ControlServer.run) | run() already does an unconditional `os.path.exists`+`os.unlink` before bind, regardless of the existing file's owner — the EACCES/EPERM failure mode that hits FrameBuffer.ensure() cannot occur here. Verified by reading the code directly and by a real ControlServer run (bind/listen/accept/PING-PONG) with a foreign-owned file present at the socket path. | 8a9860c |
| A daemon-side `sudo -n rm -f` fallback could reclaim a genuinely foreign-owned file when the direct unlink fails. | runtime/dreamconnect_daemon.py (FrameBuffer.ensure) | Rejected by design, not a code defect: no sudoers grant exists anywhere in this repo to make it succeed in production, and it gives a long-running daemon a live path to invoke sudo. Confirmed no NOPASSWD entry for this daemon exists via a repo-wide search before rejecting. | 8a9860c |
| A resource leak (stale fd/mmap) across the unlink-and-retry path in FrameBuffer.ensure(). | runtime/dreamconnect_daemon.py (FrameBuffer.ensure) | Prior self.mm/self.fd are closed before the try/except that does the unlink+retry, independent of whether the reopen succeeds — traced directly in the diff. | 8a9860c |

## Unprobed — no oracle available

| hypothesis | path | what would settle it |
|---|---|---|
| Whether an SC JVM that already has the stale shm inode mmapped picks up the reclaimed file without a restart. Traced as *closed in practice* because install.sh unconditionally restarts the SC unit after the reclaim point on the only path that triggers the cross-uid case (a migration re-run of install.sh) — but this ordering is incidental (the SC restart exists to reinstall JAVA_TOOL_OPTIONS, not because anyone sequenced it against the shm reclaim) and only the reclaim-before-restart *ordering* is pinned by a test, not reachability of a live consumer's remap behavior. | agent/boot/dreamconnect/boot/FrameReader.java (mmap remap-on-geometry-change) vs. install.sh's reclaim/restart sequence | An on-device end-to-end run: perform a real host-account migration with SC actively running, and confirm capture recovers without operator intervention. Needs a live SC/systemd/GDM session — not available in this sandbox. |
| A narrow race: if a concurrent actor removes the shm file between FrameBuffer.ensure()'s failed os.open() and its own os.unlink(), the unlink raises FileNotFoundError, uncaught. | runtime/dreamconnect_daemon.py (FrameBuffer.ensure) | Judged acceptable given the single-daemon-per-uid systemd model (no other process should be racing this unlink) — not proven impossible, just judged out of the practical threat model for this fix. A stress test with a concurrent unlinker would settle it definitively. |
