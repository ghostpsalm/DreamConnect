## Ruled out — probed with evidence, no defect found
| hypothesis | path | evidence | established at |
|---|---|---|---|
| Dropping `final` from `DaemonClient` widens the trust boundary (it runs in ScreenConnect's JVM as root). | `agent/boot/dreamconnect/boot/DaemonClient.java` | `agent/build.sh:29-30` compiles only `agent/boot`, so the test tree never ships. Class is package-private; sole construction is `Bridge.java:79`; no reflection, no other subclass. The jar is appended via `appendToBootstrapClassLoaderSearch` from a root-owned temp file, so planting a hostile `dreamconnect.boot.*` class already requires owning the JVM. | 6bd0962 |
| `FakeDaemon`'s `super("/nonexistent/…")` could do real I/O or hang the gate. | `agent/test/dreamconnect/boot/BootTests.java` | Constructor stores the path only; `ensure()` is lazy inside `send`/`input`, and `input` is overridden so it never runs. Even eager, `connect()` to a nonexistent AF_UNIX path fails fast with ENOENT. No leak; no cross-test static state beyond the `failures` counter. | 6bd0962 |
| The tests and the code agree but are both wrong against the real standards. | `agent/boot/dreamconnect/boot/AwtEvdev.java` | All 54 `KEY` values checked against `/usr/include/linux/input-event-codes.h` (incl. PRINTSCREEN→99 KEY_SYSRQ, CONTEXT_MENU→127 KEY_COMPOSE, ALT_GRAPH→100 KEY_RIGHTALT; the 125 shared by META/WINDOWS is intentional). All 47 keysyms are ASCII == X11 Latin-1, incl. the non-identity VK_QUOTE(0xDE)→39 and VK_BACK_QUOTE(0xC0)→96. No discrepancy. | 6bd0962 |
| Adding `VK_SEPARATOR` to `KEY` collides with an existing entry or breaks the disjointness guard. | `agent/boot/dreamconnect/boot/AwtEvdev.java` | Reflection over the private maps: `KEY` 55 / `KSYM` 47, intersection empty, evdev 121 has exactly one owner (vk 108); `VK_DECIMAL` still holds 83. Repo-wide grep: nothing outside AwtEvdev/BootTests enumerates the table — the daemon parses `K <int>` generically. | 6bd0962 |
| KS-before-K branch order in `sendKey` is a live risk worth testing. | `agent/boot/dreamconnect/boot/DreamConnectRobotPeer.java` | It is **unobservable**: the tables are disjoint (verified total by reflection, not just over the scanned range), so a mutant swapping the two branches passes the whole suite. Do not write a test claiming to pin it — a seraph lap already failed this slice for exactly that overclaim. The disjointness guard is what protects it instead. | 6bd0962 |
