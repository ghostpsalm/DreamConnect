# Hazards — DreamConnect (fragment: issue #22, disable_autologin backup lifecycle)

Read by the `breaker` before every red team; appended by `/submit`. Not a bug list — the issue tracker
holds work. This holds *where trouble has been found before, and what has already been ruled out*.

A rule-out is evidence only while the code it names is unchanged, which is why every row carries a path
and the commit it was established at. Expiry is checked with **both** `git log <commit>..HEAD -- <path>`
and `git diff HEAD -- <path>` — a red team works on an uncommitted tree, so `git log` alone cannot see
the change it is there to attack.

## Ruled out — probed with evidence, no defect found

| hypothesis | path | evidence | established at |
|---|---|---|---|
| A hostile/tampered `.bak` could inject content beyond a genuine `[daemon]` `AutomaticLogin`/`AutomaticLoginEnable` line into the live conf via the new `getline`-based collect/restore pass | `install-lib.sh :: disable_autologin` | Tested with `AutomaticLoginDelay=0`, `AutomaticLoginX=nope`, `WaylandEnable=INJECTED`, and a `[security]`-section `AutomaticLogin=` line in the backup — none crossed into the live conf; only genuine `[daemon]` `AutomaticLogin`/`AutomaticLoginEnable` lines matched the anchored regex. `getline` splits on newline, so no single line can forge a `[section]` header | 9e4c203 |
