# Hazards — DreamConnect (fragment: issue #24, wait_for_user_bus)

Read by the `breaker` before every red team; appended by `/submit`. Not a bug list — the issue tracker
holds work. This holds *where trouble has been found before, and what has already been ruled out*.

A rule-out is evidence only while the code it names is unchanged, which is why every row carries a path
and the commit it was established at. Expiry is checked with **both** `git log <commit>..HEAD -- <path>`
and `git diff HEAD -- <path>` — a red team works on an uncommitted tree, so `git log` alone cannot see
the change it is there to attack.

## Held — found once, now guarded by a test

| hazard | path | test that holds it | commit |
|---|---|---|---|
| `[ -S "$bus" ]` alone is satisfied forever by an orphaned socket inode left by a crashed prior `user@<uid>.service` (AF_UNIX never unlinks it on listener death) — the wait would report success while the bus still refuses every connect | `install-lib.sh::wait_for_user_bus`, `::bus_socket_is_live` | `test_wait_for_user_bus_rejects_an_orphaned_socket_that_refuses_connections` | a3989f7 |
| A non-numeric `timeout_seconds` (e.g. `"abc"`) crashed the shell on unguarded `$(( ))` arithmetic under `set -u`, bypassing the caller's `|| die` entirely | `install-lib.sh::wait_for_user_bus` | `test_wait_for_user_bus_refuses_a_non_numeric_timeout` | a3989f7 |
| A very large numeric `timeout_seconds` (e.g. `99999999999999999`) overflowed the millisecond deadline arithmetic, turning the bounded poll unbounded | `install-lib.sh::wait_for_user_bus` | `test_wait_for_user_bus_refuses_a_timeout_beyond_the_86400_second_cap`, `test_wait_for_user_bus_refuses_a_timeout_just_past_the_cap` | a3989f7 |
| A digit-only `^[0-9]+$` validation still accepted leading-zero strings (`"08"`, `"010"`); bash's `$(( ))` reads a leading zero as octal, so `"08"` (invalid octal) threw an uncaught arithmetic error that bypassed the intended `return 1`/`die` path, and `"010"` (valid octal = 8) silently waited the wrong duration instead of being refused | `install-lib.sh::wait_for_user_bus` | `test_wait_for_user_bus_refuses_a_leading_zero_timeout_that_is_not_valid_octal`, `test_wait_for_user_bus_refuses_a_leading_zero_timeout_that_is_valid_octal` | a3989f7 |

## Ruled out — probed with evidence, no defect found

| hypothesis | path | evidence | established at |
|---|---|---|---|
| The uid argument (arg 1) could carry an injection or path-traversal payload into the python3 connect probe | `install-lib.sh::bus_socket_is_live` | Path is passed as `sys.argv[1]`, never interpolated into the `-c` script text; `USER_UID` is sourced from `getent`/`id -u`, not attacker input | a3989f7 |
| `set -e` interaction inside `wait_for_user_bus`'s poll loop (the `[ -S ] && bus_socket_is_live && return 0` AND-list, or a failing `sleep`) could abort the script early with a confusing failure instead of the intended timeout message | `install-lib.sh::wait_for_user_bus` | Call site is `|| die`, suppressing errexit inside the function; every `&&`-chain is non-final in its list; a failing `sleep` degrades to a bounded busy-loop, not an abort | a3989f7 |
| `DC_RUNTIME_DIR_ROOT`/`DC_BUS_POLL_INTERVAL` test overrides could leak into a later test or a real install path if sourced in the same shell | `test_install.sh` fixtures | Env var assignments confined to `$( )` subshells; no leakage observed across the added tests | a3989f7 |
| `timeout=0` or `DC_BUS_POLL_INTERVAL=0`/non-numeric could busy-loop or hang indefinitely | `install-lib.sh::wait_for_user_bus` | `timeout=0` probes exactly once then fails fast; a zero or non-numeric interval degrades to a bounded busy-loop until the deadline, never past it | a3989f7 |
