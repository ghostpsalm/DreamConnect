## Breaker lap 2 (FINAL — budget exhausted): defect-found
1. **Real defect, in-scope, demonstrated**: `^[0-9]+$` validation (install-lib.sh:392 area) accepts leading-zero strings like `"08"`/`"010"`, which bash's `$(( ))` then parses as octal. `"08"` isn't valid octal → arithmetic expansion errors *inside* `wait_for_user_bus`, which sits on the left of the call site's `|| die`, so the crash propagates instead of `die` firing — install.sh proceeds into the exact race this issue exists to prevent (repro in breaker report: `reached the systemctl --user calls` after `wait_for_user_bus 1000 08` blows up). `"010"` is valid octal (=8 decimal) and silently waits ~8s while reporting "timed out after 010s" — wrong duration, no crash. This is lap-1 defect #2 reopened by a validator that checks digit-shape, not numeric base. **Fixing now**: force base-10 arithmetic (e.g. `10#$timeout` or strip leading zeros before use) so leading-zero strings can't hit octal parsing, and add a test for both the crash case and the silent-wrong-duration case.
2. **Test weakness, fixing alongside**: the `-gt 86400` cap clause is unasserted — deleting it entirely still leaves the suite green (86401..99999 range has no test; the existing "huge value" test is caught by the 5-char length check instead). Add a test in the 86401-99999 range that only the cap clause (not the length check) can catch.
