via mv -f on undo, consuming the backup that way. GDM's pair is the outlier that
neither restores nor cleans up — this fix makes it consistent in structure (every
backup-owning function manages its own backup's lifecycle) while keeping its
mechanism (strip, not restore) deliberately different, for the reason above.

## Reviewer follow-ups (non-blocking per reviewer's own verdict; NOT filed as GitHub issues -- token lacks issues:write scope, 403 on attempt; owner needs to file these by hand or grant the scope)

1. **enable_autologin's `cp -a "$conf" "$conf.dreamconnect.bak"` (install-lib.sh ~line 87) is non-atomic.** A crash mid-copy leaves a readable-but-truncated `.bak`, indistinguishable from "no prior autologin" to disable_autologin's fail-closed check (row 4), which only catches genuinely *unreadable* backups. Verified: a truncated `.bak` still returns 0, strips the live key, deletes the backup -- a real pre-existing AutomaticLogin is lost. Fix belongs in the writer: copy to a same-directory temp file then `mv` into place (atomic rename). Very low probability (crash during a ~1KB copy); data-loss classified but reviewer explicitly marked non-blocking.
2. **A `custom.conf` with two `[daemon]` headers gets the restored lines reprinted after each one** (install-lib.sh ~line 151-155). Cosmetic, bounded/self-correcting on the next call, same pre-existing shape already present in `enable_autologin`'s own insert logic. Not a new defect this diff introduced, just not fixed by it either.
3. **The key-matching regex `^[[:space:]]*#?[[:space:]]*AutomaticLogin(Enable)?[[:space:]]*=` is now duplicated three times** across `enable_autologin`/`disable_autologin` (lines ~96, ~142, ~160) -- exactly the kind of drift that caused row 5's duplication bug (two copies fell out of sync). Reviewer suggested factoring to a single `-v pat=` value (the pattern contains no backslashes, so `-v` is safe here, unlike the user-name hazard elsewhere in this file). Small, in-scope, no design decision needed -- deferred to a follow-up rather than another build cycle given the reviewer's own "SHIP, no blockers" verdict.
