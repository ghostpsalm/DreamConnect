## Seraph gate: FAIL — Site B's guard checks a shifted value, doesn't catch the real scenario
`resolve_host_identity` emits a space-delimited string `"$name $uid $home /run/user/$uid/dreamconnect.sock"`. When `$home` is empty (the EXACT issue #21 sub-problem 2 scenario — account deleted by hand, passwd field 6 empty), the string has a double space; bash's `read -r USER_NAME USER_UID USER_HOME _ <<<"$IDENTITY"` word-splitting on default IFS COLLAPSES the empty field, shifting the socket path into `$USER_HOME` instead of leaving it empty. Site B's `valid_home_dir "$USER_HOME"` guard then checks the socket path (which IS a valid-looking absolute path), passes, and install proceeds writing into `/run/user/$uid/dreamconnect.sock/.config/...` as if it were a home directory. The guard gives false confidence; the real scenario is NOT caught.
**Fix direction**: move validation into `resolve_host_identity` itself (the producer, in install-lib.sh — testable at the library seam, unlike install.sh's own parsing). If `resolve_host_identity` refuses when `home` is empty/invalid BEFORE ever emitting the field-shiftable string, install.sh's existing `IDENTITY="$(resolve_host_identity ...)" || die` catches it correctly with no shift possible. Site B's downstream guard becomes redundant defense-in-depth once this lands — keep or drop per builder's judgment, but it must not be presented as the fix.

**FIXED**: `resolve_host_identity` now calls `valid_home_dir "$home"` right after extracting it from the passwd entry, before ever echoing the space-delimited identity string — refuses (non-zero, no stdout, clear stderr) rather than emitting a shiftable line. Tests: test_resolve_host_identity_refuses_an_empty_home_field, test_resolve_host_identity_refuses_every_home_valid_home_dir_rejects, test_resolve_host_identity_still_resolves_a_usable_home (anti-vacuous control, unchanged), test_resolve_host_identity_never_hands_the_caller_a_shifted_home. Suite 119/119, shellcheck clean. install.sh's Site B guard left in place as harmless defense-in-depth, not claimed as the fix.

**Residual gap, flagged not fixed**: the same field-shift risk applies to a home containing WHITESPACE (not just empty) — e.g. `/home/john doe` would still shift `read`'s fields, and `valid_home_dir` deliberately has no whitespace rail (by design, to avoid slice 2's enable_autologin over-tightening mistake — though that reasoning was about usernames, not home paths, so worth owner reconsideration).
